# Known costs

Each of these is decided. What remains is a cost the decision lands on an implementation, or a limit of the suite, and a second implementation is told here rather than left to find it.

- **The string decision is cheap in Swift and dear elsewhere.** Grapheme-cluster counting and canonical equivalence come with the platform in Swift and are a library obligation in most other languages; the decision stands, and the cost lands on implementations unevenly.
- **The suite covers the constructs, the vocabulary, the encodings and the objects, and a few rules no case can hold.** Every construct, the naming and leaving rules, the version and the imports list, the doors' judgements, every standard procedure, what a binary reader must refuse and what a build writes down for each operation are held as cases, and each page names its own under *Cases*. The rest no case can hold:
  - Cancellation needs a host with a lever, which a data case is not, so stopping is held only by tests inside the implementation.
  - The concurrency grant needs a host that leaves `Standard.Concurrent` out of the link, and a runner links the standard vocabulary for every case.
  - A case writes the stage a document is refused at and no place, so which spot a refusal names, under [checking](CHECKING.md), and the line and column a text refusal names, under [encodings](ENCODING.md), are held only by tests inside the implementation. The sentence beside the place is the implementation's, and two implementations agreeing on every case may still say the reason in different words.
  - What a native procedure declares and calls is the host's code, and a case writes none of it, so a send of the host's naming a contract's procedure or reaching a `private` declaration or one taking a parameter in place, a parameter of its own asking for a procedure that takes one, and a procedure it was handed taking one, are each refused under [procedures](PROCEDURE.md), and what it hands a closure it was handed and writes through a parameter handed in place is fitted and judged at the door, each held only by tests inside the implementation.
  - A case's vocabulary always stands as a document, so a `private` native procedure in a module the host assembled with no document, refused at the load under [procedures](PROCEDURE.md), is held only by tests inside the implementation.
  - A case starts one run of its image, so that every run starts each module variable at its folded value, under [documents](DOCUMENT.md), is held only by tests inside the implementation.
  - A `Double` with no finite value reaches a door only from a host's own procedure, and what a case's vocabulary returns is written in a document's spelling, which has none, so the door refusing it, under [values](VALUE.md), is held only by tests inside the implementation.
  - A runner keys every object it compiles and every case's document is written down, so an object standing on one with no key, or holding a closure written by a document nobody wrote down or a box of the run that made it, is not written under [objects](OBJECT.md), and that is held only by tests inside the implementation.
  - A writer handed a value no reader produces, one deeper than the bound or holding infinity or NaN, refuses, and a case hands a writer only what a reader read, so those refusals are held only by tests inside the implementation.
  - A document at the nesting bound fits in no case, since the case's own mappings stand around it and add to its depth, so a reader and a writer taking one 128 deep is held only by tests inside the implementation.
  - A key a path writes into a dictionary keyed by a contract holds the type it was read as, under [types](TYPE.md), and nothing a case writes reads that type back: `Standard.Collection.keys` bounds its `Key`, and a value of a contract fills a bounded parameter only where it stands alone, so it refuses such a dictionary at the build. So the hold is held only by tests inside the implementation.
- **A folded constant key holds the type it is an instance of in a dictionary keyed by a contract.** A path writing `m[C]`, `C` a module constant, folds the key to its value, and a value an object writes holds no type, so the entry's key holds the type it is an instance of rather than the one `C` was read as, as [types](TYPE.md) says. Nothing a program does reads the difference, for the reasons no case reads a key's hold.
- **A closure read back from an object holds a standing type parameter without its bounds.** A closure value writes what fills each type parameter of the declaration that wrote it as a document writes a type, under [objects](OBJECT.md), so a closure made where a bounded type parameter was filled by no call, as at an entry, reads that parameter back by its name alone. Only the refusal of a type parameter no call filled reads it there, and that asks whether the parameter stands, not what bounds it, so no answer changes.
- **Two equivalences coexist, and the border is drawn.** Values compare as a person reads. `equal`, `contains`, ordering and `count` all read strings under canonical equivalence, stated under the value model. Names are matched as bytes and held to NFC at `load`, so a document cannot declare `é` one way and reference it the other. What remains here is only the cost: an implementation whose platform compares by code unit owes a library the difference.
- **A run's values have no bound, and an implementation walks them on its own stack.** The nesting bound is the wire's, under [encodings](ENCODING.md), and a running program builds deeper values than any document. An implementation whose comparison, rendering or release of a value recurses meets a depth there that no document brought, and owes either a walk on a stack of its own or a host that stops the run; the language refuses nothing there.
- **A build's types have no bound but an object's.** An alias may stand for one that stands for another, and a generic call returns the type its declaration returns with its type parameters read as its arguments are, so a build works out types deeper and larger than any document writes: a chain of aliases is as deep as it is long, an alias naming the one before it twice doubles at each step, and calls of a generic procedure nest what each returns inside the next. An implementation whose judgement, comparison or rendering of a type recurses, or that spells one out in full, meets a depth and a size there that no document brought; the language refuses only an object whose tables nest past the bound, under [objects](OBJECT.md), and the build goes on.
